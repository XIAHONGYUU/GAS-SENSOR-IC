# 技术HTML报告制作复盘

## 结论

这份Quarto + Reveal.js报告经历多轮返工。主要问题不是单次绘图能力，而是自然语言需求没有在执行前稳定转换为页面契约、素材契约和质量门。

## 主要错误与修正

| 问题 | 根因 | 后续规则 |
|---|---|---|
| 一次修改过多页面 | 内容、技术、视觉和隐私变更混在同一批 | 复杂修改每批3–5页 |
| 代表页覆盖不足 | 字体和配色通过，不代表论文图、AI图和表格通过 | 母版必须覆盖六类页面 |
| 无越界被误当作排版正确 | 只检查容器，没有检查图片有效信息 | 同时检查裁切、覆盖、相交和投屏尺度 |
| AI图承担精确技术语义 | 文字、箭头和底图职责混乱 | AI图负责示意，HTML/SVG负责精确关系 |
| 制作提示进入正文 | 正文与内部说明没有分离扫描 | 发布前扫描TODO、占位语和作者提示 |
| 论文身份与读出形式混淆 | 没有固定器件、测量量和禁止外推 | 每篇论文建立四字段证据卡 |
| 成本模型只看晶圆 | 没有建立系统成本树 | 同时考虑封装、测试、PCB、BOM和校准 |
| 页码漂移 | 只引用自然页码 | 使用稳定页面ID和标题 |
| 用户过晚看到关键页 | 整批完成后才集中检查 | 每批先渲染关键截图再继续 |

## 页面任务卡

每次修改前至少冻结：

```text
页面ID与标题
当前基线
观众应带走的结论
必须显示的信息
必须保留和禁止改变的内容
素材来源与使用权限
技术证据边界
视觉优先级
当前验收阶段
```

## 素材契约

- 公开论文图：记录题名、图号、来源、许可证和证据边界。
- 内部图片：只用于本地理解，不复制、不上传、不直接展示。
- AI生成图：预先定义比例、主体区、文字安全区和禁止内容。
- 图文组合：优先分区排列，覆盖式说明必须证明不遮挡有效信息。

## 双层质量门

自动检查负责页数、讲者备注、图片加载、链接、版本、字体下限、页面边界和提示语残留。人工检查负责图片有效区域、文字覆盖、论文身份、技术箭头、证据匹配和目标投屏可读性。

自动检查通过不等于用户完成视觉验收；用户签收也不替代文件身份、版权和发布边界检查。

## 发布规则

只有在内容、视觉、证据、许可和隐私均通过后，才固定版本号、记录哈希并发布。后续修改进入新版本，不在已签收HTML上直接打补丁。
